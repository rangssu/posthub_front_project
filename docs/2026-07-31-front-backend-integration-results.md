# 프론트-백엔드 로컬 통합 검증 결과 (2026-07-31)

설계: `docs/superpowers/specs/2026-07-31-front-backend-integration-design.md`

두 앱을 처음으로 붙여 브라우저에서 직접 돌린 기록이다. 검증 환경은 로컬 개발 DB `posthub`,
백엔드 로컬 `main`(미배포 51커밋), 프론트 `feat/auth-refresh-integration`.

## 1. 결론

주요 플로우가 전부 통과했다. 인증 흐름의 세 가지 결함(쿠키 미전송, 갱신 없음, 로그아웃
미전달)을 고쳤고 브라우저에서 동작을 확인했다.

## 2. 고친 것

| 문제 | 조치 |
|---|---|
| `.env`가 DNS에 없는 도메인을 가리킴 | `.env.local`로 로컬 주소를 덮음(커밋 대상 아님) |
| 리프레시 쿠키가 오가지 않음 | `withCredentials: true` |
| 401에서 즉시 로그아웃 (15분마다 튕김) | 재발급 후 원래 요청 재시도. 실패해야 로그아웃 |
| 로그아웃이 서버에 전달되지 않음 | `POST /auth/logout` 호출. 실패해도 로컬은 정리 |

## 3. 검증 결과

| # | 플로우 | 결과 |
|---|---|---|
| 1 | 회원가입 → 로그인 | 통과. `Set-Cookie: refreshToken=...; Path=/api/auth; HttpOnly; SameSite=Lax` |
| 2 | 글 작성 → 수정 → 삭제 | 통과. 삭제 후 `GET /api/posts/{id}`가 404 |
| 3 | 댓글 작성 | 통과. 한글 그대로 저장·표시 |
| 4 | 게시글 좋아요 | 통과. 카운트와 하트 상태 반영 |
| 5 | 검색 | 통과. "내용" 10,006건, "제목" 4건 |
| 6 | **액세스 토큰 만료 후 로그인 유지** | **통과.** 아래 4절 |
| 7 | 로그아웃 | 통과. 204 응답 후 리프레시가 401 |

**댓글 좋아요는 UI에서 직접 누르지 않았다.** 게시글 좋아요와 같은 `LikeButton`/`useLike`를
쓰고 단위 테스트가 덮고 있어 건너뛰었다.

## 4. 토큰 만료 복구 — 네트워크 로그

만료된 액세스 토큰을 넣고 좋아요를 눌렀을 때 실제로 오간 요청이다.

| 순서 | 요청 | 상태 |
|---|---|---|
| 1 | `POST /api/posts/2/likes` | **401** |
| 2 | `POST /api/auth/refresh` | **200** |
| 3 | `POST /api/posts/2/likes` | **200** |

재발급 요청은 **한 번만** 나갔고, 화면에는 좋아요가 정상 반영됐다. 사용자는 만료를 느끼지
못한다.

### 단일 비행이 필요한 이유를 실제로 확인했다

이미 회전된(폐기된) 리프레시 토큰으로 재발급을 시도해봤다.

| 시도 | 결과 |
|---|---|
| 폐기된 옛 토큰으로 refresh | 401 |
| **그 직후, 유효했던 새 토큰으로 refresh** | **401** |

재사용이 감지되자 **계열 전체가 폐기됐다.** 방금 전까지 멀쩡하던 토큰까지 죽는다. 프론트가
재발급을 동시에 두 번 보내면 로그인 세션이 통째로 날아간다는 뜻이고, 그래서 진행 중인
재발급을 하나로 묶는 것이 선택이 아니라 필수다.

## 5. 확인했지만 결함이 아닌 것

**검색에서 `"글 내용"`이 0건이다.** `ngram_token_size`가 2라 1글자인 `"글"`이 토큰화되지
않아서다. `"내용"`, `"제목"`, `"dydd"`는 모두 정상적으로 나온다. 백엔드 검색 방식의 특성이지
연결 문제가 아니다. 사용자 입장에서는 혼란스러울 수 있어 기록해 둔다.

**`curl`로 보낸 한글 요청이 400이었다.** 셸의 인코딩 문제였다. 브라우저에서는 제목·본문·댓글
모두 한글이 정상 처리된다.

## 6. 남은 일

- **마이페이지** — `GET`/`PUT`/`DELETE /api/users/{id}`가 프론트에 전혀 노출돼 있지 않다.
  탈퇴는 익명화라 "글은 남고 닉네임만 바뀐다"는 안내가 필요하다. 별도 spec
- **대댓글** — `POST /api/comments/{parentId}/replies`와 `CommentResponse.replies`가
  백엔드에 준비돼 있으나 화면이 없다. 별도 spec
- **마크다운 에디터** — 설계·계획 문서만 있고 미착수
- 개발 DB `posthub`에 검증 흔적이 남아 있다: 계정 `itgtest01`(userId 12), 게시글 2번의
  댓글과 좋아요. 작성한 글은 삭제 검증에 썼으므로 남아 있지 않다

## 7. 재현 방법

```powershell
# 백엔드 (MySQL, Redis 필요)
cd C:\Users\wlqkr\IdeaProjects\posthub
.\gradlew.bat bootRun

# 프론트
cd C:\Users\wlqkr\IdeaProjects\posthub-front
npm run dev
```

`.env.local`이 없으면 `.env`의 배포용 주소를 쓰게 되어 아무것도 뜨지 않는다.

액세스 토큰 만료를 재현하려면 15분을 기다리는 대신 백엔드를
`JWT_EXPIRATION_MILLIS=10000`으로 띄우거나, 브라우저에서 `localStorage.accessToken`을
잘못된 값으로 바꾼 뒤 인증이 필요한 동작을 하면 된다.
